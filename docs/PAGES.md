# Этап 6. Публичные страницы

Статус: реализовано во фронтенде, API не подключён (`docs/API.md` на момент работы не существует).

## Устройство

- `frontend/src/data/` — слой данных. `content.ts` отдаёт страницы, настройки, товар, магазины и продавца синхронно; по умолчанию берёт `fixtures.ts` (данные по форме таблиц `page`, `page_block`, `seo`, `setting`, `shops`, `product`). Когда появится API, сборка заполняет ту же структуру через `setSiteContent()`.
- `pages/static/PageView.vue` — одна страница для всех маршрутов; рисует блоки `gallery`, `text`, `product`, `shops` (`components/blocks/`). SEO — `layout/PageSeo.vue` (`useHead`).
- Маршруты: `/`, `/about`, `/shop`, `/where-to-buy`, `/privacy`, `/personal-data` (все в `includedRoutes` vite-ssg), `/cart`, `/cms`.
- Cookie-баннер: `floating/CookieBanner.vue`, текст и кнопка из настроек, согласие в cookie `cookieConsent`.
- Брейкпоинты: ≤1160 px (iPad), ≤660 px (мобильная); сетка фото 3/2/1 колонки.

## Решения

- Фото — заглушки (серые блоки с нужным соотношением сторон): из Figma их не удалось выгрузить (лимит MCP, экспорт в браузере невозможен). Нужны реальные файлы.
- Тексты страниц и SEO написаны заново. Политика конфиденциальности и согласие на обработку данных — черновик без юридической проверки.
- Цена в статической странице берётся при сборке; на этапе 7 запрашивать её у бэкенда.
- Кнопка «В корзину» работает с локальной корзиной (cookie) до этапа 7.
- Счётчики (Метрика, VK) перенесены в настройки `counter.*` для этапа 9, на страницах пока не подключены.
- Удалены личный кабинет (`Cabinet.vue`), `store/auth.ts`, `clientComponents.ts` и старые страницы `pages/static/{index,about,shop}`.
- `main.ts`: убран дубль `app.use(router)` и ожидание `router.isReady()` — с ним клиент не монтировался (vite-ssg ставит роутер сам).

## Не сверено с макетом

Вёрстка сделана по скриншотам планшетного кадра (Figma `1763:730`) и проверена в браузере на 1400, 834 и 375 px (горизонтального переполнения нет). Десктопный и мобильный кадры Figma детально не изучались; отступы, шрифты и положение блоков не сверялись пиксельно; текст «О проекте» из Figma не читался.

## Этап 7. Заказ и подключение к API

- Страницы читают `GET /api/site`. Сборка (`vite-ssg`) берёт содержимое с `API_URL` (по умолчанию `http://localhost:3001`) и передаёт его в гидратацию через `initialState`. Если API недоступен, собираются страницы из `data/fixtures.ts` (в логе предупреждение).
- `data/api.ts` накладывает ответ API на фикстуры: что CMS оставила пустым, берётся из фикстуры, пустая страница не получается.
- Цена приходит только с бэка: при сборке в `site`, при показе дополнительно `GET /api/products/:id/price`. Пара цветов = позиция `item`, в корзину уходит её `id`.
- Корзина на сервере по анонимному токену (cookie `rc_client`, HttpOnly). Значок читает `rc_cart_count`, до загрузки корзины запросов не делает.
- Маршруты `/cart`, `/order`, `/order/:number` не индексируются и исключены из статической сборки. Оформление: имя, телефон, почта, адрес (до двери или пункт выдачи с кодом), комментарий, согласие на обработку данных обязательно, форма предзаполняется из `GET /api/checkout/prefill`.
- Ошибки: поля подсвечиваются по `details`, пустая корзина, 429 и сбой сети показываются сообщением, заказ при ошибке не создаётся.
- Стоимость доставки не считается, на подтверждении «будет сообщена отдельно» (СДЭК и письма на этапе 8). Текст подтверждения про письмо заранее обещает его этапу 8.
- Экраны корзины, оформления и подтверждения в макете не нарисованы, сделаны в стиле сайта (`styles/_shop.scss`).

## Этап 9. SEO

- **Head страницы** (`src/seo/head.ts`, `PageSeo.vue`): title, description, canonical, Open Graph, `twitter:card` из SEO-записи страницы; картинка — своя или `seo.og_image`. Служебные страницы (`robots_index = 0`, корзина) получают `noindex, nofollow` без canonical, OG и JSON-LD. Для корзины, заказа, `/cms` и `/app-shell` — всегда noindex.
- **JSON-LD:** `Organization` на главной, `Product` + `Offer` на странице с товаром. **Решение по цене:** в статический HTML цена попадает на момент сборки; в браузере `ProductBlock` запрашивает `/products/:id/price` и пишет её в `livePrice`, после чего видимая цена и `Offer` обновляются реактивно. Изменение цены попадает в статику после публикации; ночную пересборку под цены «с датой» делаем на этапе 12. Автопубликация при правке цены отклонена: побочные эффекты и лишние записи публикаций.
- **sitemap.xml и robots.txt** пишутся при сборке (`build/seoFiles.ts`, `onFinished`); адрес берётся из настройки `site.url`, иначе `SITE_URL`, иначе `https://rechess.ru`. Закрыты `/cms`, `/cart`, `/order`, `/app-shell`, `/api/`. Старый `frontend/dist/robots.txt` и неиспользуемый `frontend/shop.html` удалены.
- **Картинки:** загрузки конвертируются в WebP/AVIF (`backend/src/services/images.ts`), `PhotoItem.vue` выводит `<picture>` с оригиналом как запасным вариантом.
- **Счётчики** (`src/services/counters.ts`): Яндекс Метрика и VK по номерам из `counter.*`, запускаются только после согласия в cookie-баннере (cookie `cookieConsent=accepted`); смена маршрута — `trackPage`. Google не подключён.
- **Публикация:** `frontend/scripts/publish.mjs` (см. `docs/API.md`). При `REQUIRE_API=1` сборка падает, если API недоступен, а не берёт фикстуры.
- **Динамические маршруты** (`/cart`, `/order`, `/order/:n`, `/cms`) обслуживаются веб-сервером через собранный `app-shell.html`. Правило nginx — этап 12.
- **SEO по умолчанию:** миграция `20261108000000_stage9_seo_defaults` добавляет SEO-записи страниц и настройки; тексты также лежат в `data/fixtures.ts`, так что при пустой CMS они есть.

# Этап 6. Публичные страницы

Статус: реализовано во фронтенде, API не подключён (`docs/API.md` на момент работы не существует).

## Устройство

- `frontend/src/data/` — слой данных. `content.ts` отдаёт страницы, настройки, товар, магазины и продавца синхронно; по умолчанию берёт `fixtures.ts` (данные по форме таблиц `page`, `page_block`, `seo`, `setting`, `shops`, `product`). Когда появится API, сборка заполняет ту же структуру через `setSiteContent()`.
- `pages/static/PageView.vue` — одна страница для всех маршрутов; рисует блоки `gallery`, `text`, `columns`, `product`, `colors` (`components/blocks/`). SEO — `layout/PageSeo.vue` (`useHead`).
- Маршруты: `/`, `/about`, `/shop`, `/colors`, `/privacy`, `/personal-data` (все в `includedRoutes` vite-ssg), `/cart`, `/cms`.
- Cookie-баннер: `floating/CookieBanner.vue`, текст и кнопка из настроек, согласие в cookie `cookieConsent`.
- Брейкпоинты: ≤1160 px (iPad), ≤660 px (мобильная); сетка по макету: три колонки по 540 px, зазор 30, поля 15 (iPad 20).

## Решения

- Фото выгружены из Figma в `frontend/public/media/` (jpg, webp, avif; имена `index-01…32`, `shop-1…6`, `pair-1…7`). Сид копирует их в папку загрузок, так что `/uploads/<имя>` работает.
- Тексты «О проекте», магазина, цветов и юридической страницы взяты из Figma (`frontend/src/data/content.json`, сгенерирован из файла; опечатки макета «влаение», «сделанны» сохранены). Согласие на обработку данных (`/personal-data`) — прежний черновик без юридической проверки.
- Цена в статической странице берётся при сборке; на этапе 7 запрашивать её у бэкенда.
- Счётчики (Метрика, VK) перенесены в настройки `counter.*` для этапа 9, на страницах пока не подключены.
- Удалены личный кабинет (`Cabinet.vue`), `store/auth.ts`, `clientComponents.ts` и старые страницы `pages/static/{index,about,shop}`.
- `main.ts`: убран дубль `app.use(router)` и ожидание `router.isReady()` — с ним клиент не монтировался (vite-ssg ставит роутер сам).

## Этап 10. Сверка с Figma

- **Макеты:** десктоп 1728 (`2431:458` главная, `2431:503` о проекте, `2724:181` магазин, `2724:75` цвета, `2431:511` юридическая), мобильные 428 (`2447:276`, `2447:324`, `2620:153`, `2724:122`, `2447:612`), планшет `1763:730` (старый кадр, ширина 834).
- **Меню:** три пункта строчными — «rechess», «о проекте», «магазин». «Где купить» из меню и подвала убрано: это блок страницы магазина (после «Для приобретения…», перед «Корпоративными заказами»); страница `where-to-buy` удалена мягко, `/where-to-buy` перенаправляет на `/shop`.
- **Главная:** две колонки, фото идут по строкам (80% колонки, на iPad 65%, на мобильной одна колонка 80%).
- **Магазин:** слева текст (название, описание, цена, «→ Цвета», где купить, корпоративные заказы), справа шесть фото. Выбор пары и кнопка «В корзину» перенесены на страницу цветов.
- **Цвета (`/colors`):** сетка семи пар, подпись в две строки, «+ добавить» / «– удалить» работают с серверной корзиной. Названия пар «01 пепельный / 02 антрацитовый» подписаны так же, как в макете. Hex цветов измерены по фото пар из Figma (в макете нет сплошных заливок цветов); миграция `20261110000000_stage11_polish` обновляет их в БД, только если там ещё старые значения. Стрелка «→» одна, как в кадре `2724:75` (внутри правого края второй карточки первого ряда); на телефоне её нет, горизонтальной прокрутки нет (мобильный кадр `2724:122`: одна колонка). Фото пар `pair-1..7` пересобраны: раньше все семь были одним и тем же снимком.
- **Юридическая (`/privacy`):** три колонки — реквизиты продавца (якорь `#company`, ссылка «О компании» в подвале), политика cookie, политика конфиденциальности. Страница `/personal-data` «Политика обработки персональных данных» — текст кадра `2431:650` (`content.json`, ключ `personal_data`; в БД — блок `text`, миграция переименовывает черновик).
- **Миграция** `20261109000000_stage10_figma_sync`: страница `colors` и её SEO, мягкое удаление `where-to-buy`, настройки `footer.credit`, `contact.instagram`, `shop.*`. Значения берутся из `fixtures.ts`, пока в CMS пусто.
- **Не сверено пиксельно:** сравнение сделано скриншотами с кадрами; планшетный и мобильный кадры проверены на ширинах 834 и 428.

## Этап 7. Заказ и подключение к API

- Страницы читают `GET /api/site`. Сборка (`vite-ssg`) берёт содержимое с `API_URL` (по умолчанию `http://localhost:3001`) и передаёт его в гидратацию через `initialState`. Если API недоступен, собираются страницы из `data/fixtures.ts` (в логе предупреждение).
- `data/api.ts` накладывает ответ API на фикстуры: что CMS оставила пустым, берётся из фикстуры, пустая страница не получается.
- Цена приходит только с бэка: при сборке в `site`, при показе дополнительно `GET /api/products/:id/price`. Пара цветов = позиция `item`, в корзину уходит её `id`.
- Корзина на сервере по анонимному токену (cookie `rc_client`, HttpOnly). Значок читает `rc_cart_count`, до загрузки корзины запросов не делает.
- Маршруты `/cart`, `/order`, `/order/:number` не индексируются и исключены из статической сборки. Оформление: имя, телефон, почта, адрес (до двери или пункт выдачи с кодом), комментарий, согласие на обработку данных обязательно, форма предзаполняется из `GET /api/checkout/prefill`.
- Ошибки: поля подсвечиваются по `details`, пустая корзина, 429 и сбой сети показываются сообщением, заказ при ошибке не создаётся.
- Город обязателен; по нему и способу запрашивается `GET /api/checkout/delivery`, в итоге показаны товары, доставка и сумма. Нет тарифа — способ недоступен, кнопка заблокирована (422 на сервере). На подтверждении: доставка, итого, ссылка отслеживания, когда менеджер ввёл трек.
- Экраны корзины, оформления и подтверждения в макете не нарисованы, сделаны в стиле сайта (`styles/_shop.scss`).

## Этап 9. SEO

- **Head страницы** (`src/seo/head.ts`, `PageSeo.vue`): title, description, canonical, Open Graph, `twitter:card` из SEO-записи страницы; картинка — своя или `seo.og_image`. Служебные страницы (`robots_index = 0`, корзина) получают `noindex, nofollow` без canonical, OG и JSON-LD. Для корзины, заказа, `/cms` и `/app-shell` — всегда noindex.
- **JSON-LD:** `Organization` на главной, `Product` + `Offer` на странице с товаром. **Решение по цене:** в статический HTML цена попадает на момент сборки; в браузере `ProductBlock` запрашивает `/products/:id/price` и пишет её в `livePrice`, после чего видимая цена и `Offer` обновляются реактивно. Изменение цены попадает в статику после публикации; ночную пересборку под цены «с датой» делаем на этапе 12. Автопубликация при правке цены отклонена: побочные эффекты и лишние записи публикаций.
- **sitemap.xml и robots.txt** пишутся при сборке (`build/seoFiles.ts`, `onFinished`); адрес берётся из настройки `site.url`, иначе `SITE_URL`, иначе `https://rechess.ru`. Закрыты `/cms`, `/cart`, `/order`, `/app-shell`, `/api/`. Старый `frontend/dist/robots.txt` и неиспользуемый `frontend/shop.html` удалены.
- **Картинки:** загрузки конвертируются в WebP/AVIF (`backend/src/services/images.ts`), `PhotoItem.vue` выводит `<picture>` с оригиналом как запасным вариантом.
- **Счётчики** (`src/services/counters.ts`): Яндекс Метрика и VK по номерам из `counter.*`, запускаются только после согласия в cookie-баннере (cookie `cookieConsent=accepted`); смена маршрута — `trackPage`. Google не подключён.
- **Публикация:** `frontend/scripts/publish.mjs` (см. `docs/API.md`). При `REQUIRE_API=1` сборка падает, если API недоступен, а не берёт фикстуры.
- **Динамические маршруты** (`/cart`, `/order`, `/order/:n`, `/cms`) обслуживаются веб-сервером через собранный `app-shell.html`. Правило nginx — этап 12.
- **SEO по умолчанию:** миграция `20261108000000_stage9_seo_defaults` добавляет SEO-записи страниц и настройки; тексты также лежат в `data/fixtures.ts`, так что при пустой CMS они есть.

## Правки после локальной проверки

- **Подвал.** «О компании» и «Политика конфиденциальности» вели на одну длинную страницу `/privacy` из трёх колонок; якорь `#company` не прокручивал, потому что у роутера не было `scrollBehavior`. Теперь клик открывает окно (`InfoDialog.vue`) с нужной колонкой блока `columns` страницы `privacy`: «О компании» — колонка 1, политика — колонка 3. Закрытие: Esc, крест, клик мимо; на экране до 660 px окно во весь экран. Ctrl/Cmd/средняя кнопка оставляют обычную ссылку. Прямые адреса — обычные страницы для индексации и писем. Добавлен `scrollBehavior` (якорь с отступом 70 px; при prerender отключён, jsdom не умеет `scrollTo`).
- **Цвета.** Фото на пару уже по одному; лишней была стрелка `→` в коде карточки второй пары (не слой картинки), удалена. «Три фото на цвет» по текущим данным не воспроизводятся: страница цветов даёт по одному `<img>` на пару (страница товара показывает галерею из 6 фото). Чистого исходника без слоёв Figma нет: `pair-1..7` собраны из слоёв предыдущей сессией, ключ REST Figma вернул 403, фрейм сверить не удалось.
- **Корзина и письмо.** Над названием пары — первая строка названия товара из данных (`product_name`); миниатюра пары в корзине, на странице заказа и в письме. Письмо: картинка вложена в `.eml` как inline-часть (`cid:item-<id>@rechess`, JPEG 160 px через sharp), а не ссылкой: публичного адреса сайта для писем нет, и почтовики часто блокируют внешние картинки.
- **Замечание, не исправлено:** текст страницы `/personal-data` — текст политики cookie, а не обработки персональных данных (проверить содержание у заказчика).
- **Тесты.** Jest больше не зависит от `PAYMENT_PROVIDER` в `.env`: `src/testing/env.ts` ставит его пустым (оплаты нет), `payment.test.ts` задаёт нужное значение сам.

## Аудит prerender и форматов картинок

- **Prerender (7 страниц).** Title, description и `h1` есть на всех, кроме `app-shell` (пустая оболочка для корзины, заказа и `/cms`, так задумано). JSON-LD только на `/` (Organization) и `/shop` (Product); на `/about`, `/colors`, `/privacy`, `/personal-data` его нет. На главной в HTML около 155 символов текста: она почти целиком из фото.
- **Форматы.** `<picture>` с AVIF, WebP и запасным JPEG; Chrome на `/shop` грузит `.avif` (860 px при показе 432). Нет `sizes` и нескольких ширин в `srcset` (одна ширина на формат), нет `width`/`height` (вместо них `aspect-ratio`, сдвигов нет). `loading="lazy"` стоит на всех картинках, включая первый экран, это вредит LCP.
- **Вес (gzip, суммы по всем фото; с lazy на старте грузится меньше).** Главная: HTML 8 КБ, JS и CSS 63 КБ, 32 фото: AVIF 2,1 МБ, WebP 3,6 МБ, JPEG 3,6 МБ. Товар: HTML 8 КБ, JS и CSS 63 КБ, 6 фото: AVIF 317 КБ, WebP 522 КБ, JPEG 587 КБ. Замер в браузере только для `/shop`.

## Осмотр витрины глазами (dev-сервер, Chrome-панель)

- **`/shop`.** Шесть фото одним вертикальным столбцом справа от текста (десктоп 1440: колонка 432 px, фото 432×543, одно 432×344; iPad 820: 239×300). Карусели, переключения и увеличения нет: курсор обычный, клик ничего не делает. Фото: коробка с доской, открытая коробка с фигурами, фигуры и доска сверху.
- **`/colors`.** Семь карточек, на каждой одно фото 1:1, на нём две фигуры (серая слева, цветная справа). Десктоп: 3 колонки по 445 px; iPad 820: 2 колонки по 368 px; телефон 375: одна колонка 345 px, горизонтальной прокрутки нет. Наведение и клик по фото ничего не меняют; действует только «+ добавить».
- **Окно подвала на телефоне (375×812).** «О компании» открывается на весь экран, текст и крест видны, горизонтальной прокрутки нет.
- **«Три фото на цвет»** на этих трёх размерах не воспроизводятся; ближайшее — две фигуры на одном снимке пары.

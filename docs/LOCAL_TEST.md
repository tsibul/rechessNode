# Локальный ручной тест

Проверено 2026-11-06 на `main` (710d588): миграции, сид, покупка с заглушкой оплаты, письмо, CMS, публикация.

## Подготовка

Нужна MariaDB с БД `rechess` и `backend/.env` (шаблон `backend/.env.example`). В `.env` должно стоять `PAYMENT_PROVIDER=stub`.
Бэкенд читает `.env` только при запуске: если он уже работает, перезапустите его (`PAYMENT_PROVIDER` не подхватится на лету). Без `stub` заказ оформляется, но экрана оплаты нет.

```bash
cd backend && npx knex migrate:latest
```

Тестовые данные (7 пар цветов, товар, пользователи CMS, клиент, корзина) создаёт сид. Он стирает каталог, заказы, клиентов, корзины и пользователей, справочники и тарифы доставки не трогает:

```bash
cd backend && npx knex seed:run
```

## Запуск

Бэкенд (порт 3001 по умолчанию, меняется `PORT`):

```bash
cd backend && npm run dev
```

Фронт с прокси `/api` и `/uploads` на `localhost:3001` (порт 3000):

```bash
cd frontend && npm run dev
```

Если порт 3001 занят (например, бэкенд из IDE), остановите его и запустите заново: прокси фронта жёстко смотрит на 3001.

## Адреса

- Сайт: http://localhost:3000/ (товар `/shop`, пары цветов `/colors`, корзина `/cart`, заказ `/order`)
- CMS: http://localhost:3000/cms
- API: http://localhost:3001/api

## Тестовые логины CMS

`admin` (администратор), `manager` (менеджер), `senior` (старший менеджер). Пароль общий, он в константе `TEST_PASSWORD` файла `backend/src/db/seeds/01_dev_data.ts`.

## Покупка с заглушкой

1. `/colors`: принять баннер cookie, у любой пары нажать «добавить», открыть корзину (значок «(1)»).
2. В корзине «к оформлению» → `/order`. Заполнить имя, фамилию, телефон, e-mail, город, адрес, отметить согласие, отправить.
3. Откроется `/order/<номер>/pay`: «деньги не списываются», сумма с доставкой. «Отказ» показывает «не прошла», «повторить» возвращает к выбору, «Оплатить» ведёт на `/order/<номер>` со статусом «оплачен».
4. Корзина после заказа пуста.

## Письма

SMTP локально не нужен: письмо заказа кладётся файлом `.eml` в `backend/outbox/` (имя начинается со времени, содержит e-mail покупателя). Папку можно сменить `MAIL_OUTBOX_DIR`. Тему закодировано в base64, читается любым почтовым клиентом.

## CMS

Вход на `/cms`. «Заказы» → строка заказа: покупатель, доставка, оплата («провайдер stub, деньги не списывались»), позиции, статус, трек, повторная отправка письма.

## Публикация

«Публикация» → «Опубликовать» → подтвердить диалог браузера. Бэкенд запускает `PUBLISH_COMMAND` (по умолчанию `node ../frontend/scripts/publish.mjs`): собирает статический сайт из текущих данных CMS в `site/releases/<время>` и переключает ссылку `site/current`. Папка `site/` в git не входит. Dev-сервер на 3000 не меняется, он и так показывает живые данные. Сборка читает данные с `API_URL` (по умолчанию `http://localhost:3001`). Занимает меньше минуты, журнал запусков внизу страницы.

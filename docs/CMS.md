# CMS (этап 5)

Интерфейс: `/cms` (страница `frontend/src/pages/dynamic/CMS.vue`, не попадает в SSG, внутри `ClientOnly`). Код: `frontend/src/cms/`, состояние входа: `frontend/src/store/cms.ts`. Макета нет, вид сделан в стиле сайта: чёрно-белый, боковое меню, таблица и форма в модальном окне.

## Устройство

- `registry.ts` описывает все разделы: таблица API, право, колонки, поля формы, фильтры, подчинённые разделы. Новый раздел для обычной таблицы — одна запись.
- `logic.ts` — проверка полей, сбор тела запроса, предпросмотр SEO, преобразования настроек. Без Vue, покрыт тестами.
- `api.ts` — клиент `/api/cms` (cookie `rc_cms`, при 401 вход сбрасывается), `refs.ts` — кэш справочников для выпадающих списков.
- Разделы по виду: таблица с формой (`TableSection`), настройки по группам (`SettingsSection`), роли и права (`RolesSection`), публикация с журналом (`PublishSection`). Заказы и корзины открываются карточкой с позициями (`Details`).
- Меню строится по правам пользователя (`visibleSections`). Разделы без права не показываются; сервер всё равно проверяет право сам.

## Разделы

Каталог: товары, пары цветов (с фото пары), цвета, цены. Сайт: страницы (с блоками), SEO (предпросмотр поисковой выдачи и карточки соцсетей), настройки, фото главной, «Где купить» (магазины с фото), продавец. Продажи: заказы (карточка: доставка, вес, трек, отметки писем, кнопки повторной отправки), тарифы доставки (право `prices`),  клиенты, корзины (в том числе брошенные), статусы заказа. Система: пользователи, роли и права, публикация.

## Решения

1. Навигация через `#раздел`, без нового маршрутизатора: страница CMS одна, обновление страницы сохраняет раздел.
2. Подчинённые записи (фото пары, блоки страницы, фото магазина) правятся внутри формы родителя, отдельных пунктов меню у них нет.
3. Удаление мягкое, в списке переключатель «Активные / Удалённые / Все» и «Восстановить».
4. Бэкенд: добавлено чтение таблиц `product`, `order_state`, `page` смежным правам (см. `docs/API.md`, «Таблицы»). Других изменений API не потребовалось.
5. Булевы настройки хранятся как `1`/`0`, пустое текстовое значение отправляется как `null`.
6. Загруженные фото отдаются с `/uploads/<имя>`; в dev-прокси добавлен `/uploads`.

7. Настройки этапа 9: `seo.og_image` (картинка карточки соцсетей по умолчанию), `social.vk`; номера счётчиков — `counter.*` (см. `docs/PAGES.md`, этап 9).

## Проверка в браузере

- Роли «простой менеджер», «старший менеджер» и админ проверены в браузере (этап 10, `e2e/tests/cms.spec.ts`): меню, запреты API (403), карточка заказа, тарифы, правка настройки с публикацией, загрузка фото в форме. Макет CMS на планшете (768 px) и телефоне (390 px) проверен `cms-layout.spec.ts`: все разделы, формы, кнопка «Сохранить» без горизонтальной прокрутки страницы.

## Карточка клиента и корзины (проверка менеджера)

- «Клиенты» → строка клиента: контакты, адрес и **история заказов** (номер, дата, сумма, статус, оплата), итоговая сумма и число неоформленных корзин. Данные даёт `decorate` таблицы `client` (`orders`, `orders_sum`, `open_carts`).
- «Заказы» → строка заказа: покупатель, телефон, почта, адрес, оплата, позиции, согласие, письма.
- «Корзины» → список с фильтрами «Брошенные (дольше 24 ч)» и «Не оформленные»; строка корзины показывает клиента, состав и время изменения. Отдельной связи «брошенная корзина → клиент → его заказы» нет, переход вручную через «Клиенты».
- Телефон и почта видны менеджерам с правами `orders`, `clients`, `carts`. Токен клиента и IP скрыты.

## Контакты: где выводятся и где правятся

Правка видна на сайте после «Публикация → Опубликовать» (контакты попадают в статический HTML при сборке); письма читают настройки в момент отправки.

| Контакт | Где выводится | Где правится в CMS |
|---|---|---|
| Телефон | подвал, письма заказа и трека (строка контактов), JSON-LD `Organization.telephone` | Настройки → `contact.phone` |
| E-mail | подвал, письма, JSON-LD | Настройки → `contact.email` |
| Ссылка WhatsApp | ссылка на телефон в подвале, JSON-LD `sameAs` | Настройки → `contact.whatsapp` |
| Instagram | подпись в подвале (текст, не ссылка) | Настройки → `contact.instagram` |
| VK / twitter | JSON-LD `sameAs`, мета `twitter:site` | Настройки → `social.vk`, `social.twitter` |
| Подпись подвала | подвал | Настройки → `footer.credit` |
| Реквизиты, «О компании» | окно «О компании» в подвале и `/privacy#company` | Страницы → `privacy` → блок колонок, колонка 1 |
| Продавец (ИНН, ОГРН, адрес) | таблица «Продавец» (`seller`) | Сайт → «Продавец» |
| Где купить (адрес, телефон, сайт, часы) | страница товара | Сайт → «Где купить» |
| Текст «Для приобретения пишите на почту…» | страница товара | Настройки → `shop.buy_note` (адрес вписан в текст отдельно: при смене e-mail поправить и здесь) |
| Имя отправителя писем | письма | Настройки → `mail.from_name` |
| Адрес отправителя писем | письма | **не в CMS**: переменная `MAIL_FROM` в `.env` бэкенда (настройка почтового сервера) |

Значения из `data/fixtures.ts` и `content.json` — только запасные для разработки без API. После ответа API пустое значение контакта остаётся пустым и не возвращает демо-значение (`CMS_OWNED` в `data/api.ts`); магазины без записей в CMS не подставляются из макета.

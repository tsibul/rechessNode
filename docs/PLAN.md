# План работ reChess

Задача: сайт с CMS. Наполнение не входит в разработку: всё настраиваемое заказчик вводит через CMS, для разработки хватает тестовых данных и макета Figma.

## Решения

- Сейчас товар один, варианты — допустимые пары цветов. Другой товар возможен, например без коробки, со своей ценой: база это допускает, экрана каталога нет.
- Категории «наличие» в проекте нет: это производство.
- Покупка без авторизации, входа и кабинета: заказ, подтверждение на почту, затем трек СДЭК.
- Корзина хранится на сервере, брошенные корзины видны в CMS. Посетителя с корзиной опознаёт анонимный токен: это не вход.
- В CMS настраивается максимально всё. В коде остаются структура страниц, в окружении секреты.
- CMS: две роли, менеджер и админ. Права описаны в `docs/PROJECT_ANALYSIS.md`, пока их не подтвердит заказчик.
- Рендер: vite-ssg с пересборкой при публикации из CMS. Цена всегда запрашивается у бэка.
- Дизайн берётся из Figma, файл `1JQIIGjT6IuowuEtPNL1jt`. Образец планшета: `1763:730` в архиве (`524:736`). Макета CMS нет, её интерфейс проектируется в работе.
- Не нарисовано и делается в стиле макета: подтверждение заказа, ошибки, пустая корзина, письма.
- Оригиналы фото подставляются по мере нахождения.
- Счётчики: Метрика, VK, twitter:card остаются; Google не используется.
- Боевой сервер и проект `rechess2` не трогать.

|---|---|---|---|
| 0 | Окружение | Переустановка `node_modules`, локальная БД `rechess` (`sudo` запускает заказчик), запуск в IDEA | Фронт и бэк работают локально |

| 3 | Модель данных | Новая миграция поверх `init`: товар со связью с парами и ценой, цена в позиции заказа, связь фото магазина с магазином, часы работы партнёров, в заказе стоимость доставки, статус оплаты (только поле), комментарий, согласие; название продавца; роль пользователя; страницы, SEO, настройки. | 4 | API | Публичное: токен в HttpOnly cookie с созданием при первом добавлении в корзину, корзина, цена, пары, заказ, данные страниц. Для CMS: вход, роли, справочники, загрузка фото, заказы, клиенты, корзины, страницы, SEO, настройки, запуск пересборки. Убрать шаблонные маршруты | Рабочее API с тестами |
| 5 | CMS | Вход и две роли. Справочники, фото, страницы, SEO с предпросмотром, настройки. Заказы, клиенты, брошенные корзины. Кнопка публикации | Рабочая админка |
| 6 | Публичные страницы | По Figma: главная, «О проекте», товар, «Где купить», политики, cookie-баннер; десктоп, iPad, мобильная. Содержимое из CMS. Убрать кабинет и остатки шаблона | Вёрстка по макету |
| 7 | Заказ | Серверная корзина без входа, значок корзины, оформление с подстановкой адреса, подтверждение, ошибки, пустая корзина; согласие на обработку данных. Цена и сумма считаются на бэке | Заказ создаётся |
| 8 | СДЭК и письма | Доставка до двери и в пункт выдачи, стоимость в заказе, трек, письма с подтверждением и треком. Тексты писем из CMS | Заказ доходит до отправки |
| 9 | SEO | Вывод полей из CMS, JSON-LD, sitemap, robots, WebP/AVIF, счётчики с номерами из CMS, пересборка при публикации | Страницы готовы к индексации |
| 10 | Приёмка | Тесты, Playwright, скорость | Сайт работает без оплаты |
| 11 | Оплата | Выбор сервиса, подключение, чеки (54-ФЗ) | Полный путь покупки |
| 12 | Выкладка | Только по команде заказчика | Боевой сервер обновлён |

## Порядок работы

- Каждый этап: отдельная сессия `rechess: <блок>` и своя ветка, не более двух сессий одновременно, рутина на Sonnet.
- Сами: чтение, локальные запуски, технические правки внутри согласованного этапа, коммиты в ветке этапа по навыку `git-commit`.
- По команде заказчика: старт этапа, слияние, видимые тексты и дизайн, зависимости, удаление файлов, настройки GitHub.
- Пуш и выкладку выполняет заказчик.

# План работ reChess

Задача: сайт с CMS. Наполнение не входит в разработку: всё настраиваемое заказчик вводит через CMS, для разработки хватает тестовых данных и макета Figma.

## Решения

- Товар один, варианты — допустимые пары цветов. База допускает другой товар, экрана каталога нет.
- Категории «наличие» в проекте нет: это производство.
- Покупка без авторизации, входа и кабинета: заказ, подтверждение на почту, затем трек СДЭК.
- Рендер: vite-ssg с пересборкой при публикации из CMS. Цена всегда запрашивается у бэка.
- Дизайн берётся из Figma, файл `1JQIIGjT6IuowuEtPNL1jt`. Образец планшета: `1763:730` в архиве (`524:736`). Макета CMS нет, её интерфейс проектируется в работе.
- Не нарисовано и делается в стиле макета: подтверждение заказа, ошибки, пустая корзина, письма.
- Оригиналы фото подставляются по мере нахождения.
- Счётчики: Метрика, VK, twitter:card остаются; Google не используется.
- Боевой сервер и проект `rechess2` не трогать.

## Этапы

| # | Этап | Что делаем | Результат |
|---|---|---|---|
| 0 | Окружение | Переустановка `node_modules`, локальная БД `rechess` (`sudo` запускает заказчик), запуск в IDEA | Фронт и бэк работают локально |
| 1 | Git | Коммит двух правок, LF, `knextry` → `main` | Чистая основа |
| 2 | Анализ кода | Сверить код с решениями: что оставить, переделать, убрать (кабинет, авторизация покупателей, клиентский токен) | Список на удаление и доработку |
| 3 | Модель данных | Товар, цвета, пары, цена, заказ, страницы, SEO, настройки; миграции; тестовые данные. Статус оплаты только как поле | Новая схема БД |
| 4 | API | Публичное: цена, пары, заказ. Для CMS: вход, редактирование, запуск пересборки | Рабочее API с тестами |
| 5 | CMS | Редактирование всего настраиваемого, SEO с предпросмотром, заказы, кнопка публикации | Рабочая админка |
| 6 | Публичные страницы | По Figma: главная, «О проекте», товар, политики, cookie-баннер; десктоп, iPad, мобильная | Вёрстка по макету |
| 7 | Заказ | Корзина без входа, оформление, подтверждение, ошибки, пустая корзина; согласие на обработку данных | Заказ создаётся |
| 8 | СДЭК и письма | Доставка, подтверждение на почту, трек | Заказ доходит до отправки |
| 9 | SEO | Вывод полей из CMS, JSON-LD, sitemap, robots, WebP/AVIF, счётчики, пересборка при публикации | Страницы готовы к индексации |
| 10 | Приёмка | Тесты, Playwright, скорость | Сайт работает без оплаты |
| 11 | Оплата | Выбор сервиса, подключение, чеки (54-ФЗ) | Полный путь покупки |
| 12 | Выкладка | Только по команде заказчика | Боевой сервер обновлён |

## Порядок работы

- Каждый этап: отдельная сессия `rechess: <блок>` и своя ветка, не более двух сессий одновременно, рутина на Sonnet.
- Сами: чтение, локальные запуски, технические правки внутри согласованного этапа, коммиты в ветке этапа по навыку `git-commit`.
- По команде заказчика: старт этапа, слияние, видимые тексты и дизайн, зависимости, удаление файлов, настройки GitHub.
- Пуш и выкладку выполняет заказчик.

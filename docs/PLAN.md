# План работ reChess

Задача: сайт с CMS. Наполнение не входит в разработку: всё настраиваемое заказчик вводит через CMS, для разработки хватает тестовых данных и макета Figma.

## Решения

- Принцип работы (06.11.2026): заказчик поручил собрать проект от начала до конца по представлениям разработки. Заказчика спрашиваем только в крайнем случае. Наполнение и SEO-тексты пишем сами, фото берём из Figma, спорное решаем сами и записываем здесь и в документах этапа.

- Сейчас товар один, варианты — допустимые пары цветов. Другой товар возможен, например без коробки, со своей ценой: база это допускает, экрана каталога нет.
- Категории «наличие» в проекте нет: это производство.
- Покупка без авторизации, входа и кабинета: заказ, подтверждение на почту, затем трек СДЭК.
- Доставка: заказчик предлагает ручную таблицу тарифов, стоимость API СДЭК не проверена. В заказе есть `delivery_cost`, пустое значение — доставка не считалась или не входит в заказ. Источник стоимости решается на этапе 8.
- Вопрос заказчика «А если это не шахматы?» отложен; модель товара по нему не менялась.
- Корзина хранится на сервере, брошенные корзины видны в CMS. Посетителя с корзиной опознаёт анонимный токен: это не вход.
- В CMS настраивается максимально всё. В коде остаются структура страниц, в окружении секреты.
- CMS: админ заводит пользователей. Принят вариант Б: менеджер простой (заказы, клиенты, корзины) и старший (ещё справочники, цены, SEO, публикация). Набор ролей и прав хранится в данных.
- Рендер: vite-ssg с пересборкой при публикации из CMS. Цена всегда запрашивается у бэка.
- Дизайн берётся из Figma, файл `1JQIIGjT6IuowuEtPNL1jt`. Образец планшета: `1763:730` в архиве (`524:736`). Макета CMS нет, её интерфейс проектируется в работе.
- Не нарисовано и делается в стиле макета: подтверждение заказа, ошибки, пустая корзина, письма.
- Оригиналы фото подставляются по мере нахождения.
- Счётчики: Метрика, VK, twitter:card остаются; Google не используется.
- Боевой сервер и проект `rechess2` не трогать.

## Этапы

| # | Этап | Что делаем | Результат |
|---|---|---|---|
| 0 | Окружение | Переустановка `node_modules`, локальная БД `rechess` (`sudo` запускает заказчик), запуск в IDEA | Фронт и бэк работают локально |
| 1 | Git | Коммит двух правок, LF, `knextry` → `main` | Чистая основа |
| 2 | Анализ кода | Сверить код с решениями: что оставить, переделать, убрать (кабинет, авторизация покупателей). Клиентский токен остаётся, см. `docs/PROJECT_ANALYSIS.md` | Анализ и предложения |
| 3 | Модель данных | Новая миграция поверх `init`: товар со связью с парами и ценой, цена в позиции заказа, связь фото магазина с магазином, часы работы партнёров, в заказе стоимость доставки (если решат хранить), статус оплаты (только поле), комментарий, согласие; название продавца; роль пользователя (набор ролей не ограничивать двумя); страницы, SEO, настройки. Начальные статусы, тестовые данные | Схема под все решения |
| 4 | API | Публичное: токен в HttpOnly cookie с созданием при первом добавлении в корзину, корзина, цена, пары, заказ, данные страниц. Для CMS: вход, роли, справочники, загрузка фото, заказы, клиенты, корзины, страницы, SEO, настройки, запуск пересборки. Убрать шаблонные маршруты | Рабочее API с тестами |
| 5 | CMS | Вход и две роли. Справочники, фото, страницы, SEO с предпросмотром, настройки. Заказы, клиенты, брошенные корзины. Кнопка публикации | Рабочая админка |
| 6 | Публичные страницы | По Figma: главная, «О проекте», товар, «Где купить», политики, cookie-баннер; десктоп, iPad, мобильная. Содержимое из CMS. Убрать кабинет и остатки шаблона | Вёрстка по макету |
| 7 | Заказ | Серверная корзина без входа, значок корзины, оформление с подстановкой адреса, подтверждение, ошибки, пустая корзина; согласие на обработку данных. Цена и сумма считаются на бэке | Заказ создаётся |
| 8 | СДЭК и письма | Доставка до двери и в пункт выдачи, источник стоимости (ручная таблица или API СДЭК) выбрать, трек, письма с подтверждением и треком. Тексты писем из CMS | Заказ доходит до отправки |
| 9 | SEO | Вывод полей из CMS, JSON-LD, sitemap, robots, WebP/AVIF, счётчики с номерами из CMS, пересборка при публикации | Страницы готовы к индексации |
| 10 | Приёмка | Тесты, Playwright, скорость | Сайт работает без оплаты |
| 11 | Оплата | Выбор сервиса, подключение, чеки (54-ФЗ) | Полный путь покупки |
| 12 | Выкладка | Только по команде заказчика | Боевой сервер обновлён |

## Порядок работы

- Один блок — одна сессия `rechess: <блок>` и своя ветка. Независимые блоки идут параллельно, зависимые по очереди. Рутина на Sonnet, проектирование на Opus.
- Сами: чтение, локальные запуски, зависимости и удаление файлов внутри блока, решения по схеме, API, интерфейсу и текстам, коммиты в ветке блока по навыку `git-commit`.
- Заказчика спрашиваем только в крайнем случае: то, что нельзя решить из кода, макета и документов и что нельзя исправить позже.
- Запрещено без команды заказчика: пуш, слияние в `main`, выкладка, боевой сервер, `rechess2`, команды с `sudo`.
- Спорные решения записываются в документ блока с причиной, чтобы заказчик мог их отменить.
